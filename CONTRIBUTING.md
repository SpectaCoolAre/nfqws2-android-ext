# Как вносить изменения без поломанных слияний

## Где что лежит в WebUI

WebUI разложен по файлам, чтобы правки разных экранов не сталкивались в одном месте:

| Файл | Что внутри |
|---|---|
| `webroot/index.html` | только разметка экранов, листов и диалогов, иконки, подключение css/js |
| `webroot/css/base.css` | токены Material 3 и базовые компоненты (кнопки, списки, поля) |
| `webroot/css/app.css` | стили экранов приложения поверх base.css |
| `webroot/js/core.js` | утилиты, язык, мост к модулю, меню, диалоги, навигация, жест «Назад» |
| `webroot/js/status.js` | экран «Состояние» и выбор стратегии |
| `webroot/js/lists.js`, `logs.js`, `config.js` | экраны «Списки», «Журналы», «Конфиг» |
| `webroot/js/editor.js` | полноэкранный редактор и подсветка синтаксиса |
| `webroot/js/apps.js`, `test.js`, `diag.js`, `settings.js` | экраны из настроек |
| `webroot/js/theme.js` | генератор палитры и лист темы |
| `webroot/js/i18n-en.js` | английский словарь: ключ — русская строка интерфейса |
| `webroot/js/init.js` | запуск, подключается последним |

Скрипты подключаются обычными `<script>` по порядку и делят одну глобальную
область. Новый файл добавляйте в `index.html` перед `init.js`.

## Перед слиянием

1. **Сначала подтяните main в свою ветку** (на GitHub — кнопка *Update branch*
   в PR, локально — `git merge origin/main`) и разрешите конфликты там, а не
   в момент слияния PR.
2. **Не выбирайте «принять всё входящее/текущее» для конфликта в коде.**
   Каждый блок конфликта — это две правки одного места; почти всегда нужны обе.
   Если неясно, как их совместить, лучше отменить слияние (`git merge --abort`)
   и спросить автора второй правки.
3. **Дождитесь зелёной проверки `check`** в PR. Она ловит забытые маркеры
   конфликта, синтаксические ошибки в shell-скриптах и в js WebUI, а также
   битые ссылки index.html на css/js. Красная проверка — не сливать.
4. Держите PR небольшими и короткоживущими: чем дольше ветка живёт отдельно
   от main, тем больше конфликтов при слиянии.

## DNS по профилям

Код DNS — `lib/dns.sh`, `webroot/js/dns.js` и пресеты в `defaults/dns-presets/`.
Резолвит AdGuard dnsproxy: в репозитории его нет, `release.yml` скачивает его
при сборке (версия и контрольные суммы архивов — в `.github/dnsproxy.lock`) и
кладёт в архив рядом с nfqws2. Без `bin/dnsproxy` (например, при запуске
тестов) DNS считается выключенным, и вызовы `dns_*` в `service.sh` и
`nfqws2-ctl` ничего не делают. Тесты DNS (`test_dns.sh`, `test_dns.js`) идут
вместе со всеми.

## Синхронизация с оригиналом

Форк подтягивает код из [nfqws2-android](https://github.com/Dea1hwa1cher/nfqws2-android).
Изменения оригинала переносятся вручную, по одному, с прогоном тестов: id
модуля, пути `/data/adb/modules/nfqws2-android-ext`, ссылки и сборка с
dnsproxy здесь свои.

## Выпуск релиза

1. Поднимите `version` и `versionCode` в `module.prop`, опишите изменения в `changelog.md`
   под заголовком `### Изменения в vX.Y.Z:` (накопленное под «в следующей версии» —
   переименуйте): по нему `release` берёт текст релиза.
2. Закоммитьте в `main` и дождитесь зелёной проверки `check`.
3. Поставьте тег с той же версией (`git tag v1.6.3 && git push origin v1.6.3`)
   или запустите вручную Actions → **release** → *Run workflow* с этой версией.

Workflow `release` сам соберёт `nfqws2-android-ext-<версия>.zip` (модуль,
nfqws2 и dnsproxy), опубликует его с текстом из `changelog.md` и обновит
`update.json` — менеджеры предложат обновление.
Релиз можно выпустить и вручную через сайт: тогда `update-json` обновит
`update.json` при публикации.
